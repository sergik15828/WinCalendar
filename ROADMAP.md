# План доработок WinCalendar

## Текущее поведение

- На панели задач — день недели и число, без нижнего индикатора запущенного приложения после закрепления.
- По обычному клику открывается Google Calendar в браузере.
- Автозапуск обновляет дату в фоне и не открывает браузер.
- Настройки автозапуска и выход доступны через `Settings.cmd`.

Это простой переход на сайт. Следующие этапы добавят локальный календарь и события Google непосредственно в приложение.

## 1. Календарь по клику

Вместо немедленного открытия браузера показывать компактную панель возле значка:

- Сетка месяца, неделя с понедельника, выделение сегодняшнего и выбранного дня.
- Переключение месяцев и кнопка «Сегодня».
- Выбор даты без изменения сегодняшнего числа на значке.
- Кнопка «Открыть Google Calendar» в панели.
- Повторный клик, Esc или клик вне панели закрывают её.
- Панель появляется на нужном мониторе и не выходит за рабочую область.
- Панель не создаёт отдельную кнопку или индикатор открытого приложения в панели задач.

**Готово, когда:** клик по закреплённой дате открывает календарь, автозапуск остаётся невидимым, дата и отсутствие нижней полоски сохраняются.

## 2. Подключение Google-аккаунта

- Добавить «Подключить Google Calendar» и «Отключить аккаунт».
- Открывать вход Google в системном браузере: Desktop OAuth, authorization code + PKCE, локальный loopback callback. Пароль Google приложение не получает. [Документация Google](https://developers.google.com/identity/protocols/oauth2/native-app).
- Начать с одного аккаунта и основного календаря `primary`.
- Запросить только чтение событий: `calendar.events.readonly`. Отдельное разрешение `calendar.calendarlist.readonly` добавлять при реализации выбора дополнительных календарей. [Разрешения Calendar API](https://developers.google.com/workspace/calendar/api/auth).
- Пользовательские токены хранить в Windows Credential Manager. Значения секретов и токенов не помещать в исходники, обычные файлы, логи или GitHub.
- Подготовить Google Cloud project с включённым Calendar API и OAuth-клиентом Desktop. Для распространения приложения учесть требования Google к экрану согласия и проверке запрашиваемого доступа.

**Готово, когда:** аккаунт подключается через браузер, сессия восстанавливается после перезапуска, отключение удаляет локальные учётные данные. Календарь без подключения продолжает работать локально.

## 3. Встречи в локальном календаре

- Загружать события для отображаемого диапазона дат.
- Помечать дни со встречами точкой или другим небольшим маркером.
- Под сеткой показывать события выбранного дня: время начала и окончания, название; отдельно обозначать события на весь день.
- Раскрывать повторяющиеся встречи и учитывать исключения, отменённые события, многодневные события и часовые пояса.
- Использовать `events.list` с диапазоном времени, `singleEvents=true`, сортировкой по началу и обработкой страниц результатов. [Events: list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list).
- При открытии панели показывать кеш сразу, затем обновлять данные. Во время подключения обновлять периодически, не блокируя интерфейс.
- Различать состояния «Нет событий», «Загрузка», «Нет сети» и «Нужно повторно войти». При временных ошибках сохранять последние данные и ограничивать частоту повторных запросов.

**Готово, когда:** в сетке видно, в какие дни есть встречи, а для выбранной даты — их понятный список в локальном времени пользователя.

## 4. Переход к Google Calendar

- Нажатие на встречу открывает именно это событие в браузере по полю `htmlLink`, которое возвращает Google Calendar API. [Ресурс события](https://developers.google.com/workspace/calendar/api/v3/reference/events).
- Кнопка «Открыть Google Calendar» ведёт на сайт календаря.
- Для переходов использовать HTTPS и системный браузер. Приложение не создаёт и не изменяет встречи.

**Готово, когда:** пользователь видит встречу в панели, нажимает на неё и попадает на соответствующее событие в Google Calendar.

## Порядок реализации и проверка

1. Локальная панель месяца и список событий на тестовом источнике.
2. Вход Google и защищённое хранение сессии.
3. Реальные события, маркеры дней, обновление и кеш.
4. Переходы к событиям и обработка ошибок.

Для UI и автоматических тестов использовать синтетические события. Проверить Новый год, високосный февраль, смену часового пояса, повторяющиеся и многодневные встречи, отсутствие сети, отзыв доступа, сон и автозапуск. После каждого этапа отдельно проверять закреплённый значок на настоящей панели задач.

Текущий клик с открытием сайта остаётся рабочим, пока следующий этап не будет реализован и проверен.
